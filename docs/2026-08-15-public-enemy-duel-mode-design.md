# 双人决战 · 天下公敌机制 设计文档

- **日期**：2026-08-15
- **文件**：`hualianhistory/quiz-battle.html`
- **状态**：✅ 已获用户批准
- **前置**：组别对决天下公敌已上线（commit `add0e26`），本设计沿用其机制并移植到双人决战

---

## 背景

- 组别对决（`gameMode='group'`）已有「天下公敌」平衡机制：连胜 5 场晋升王者 → 其余组别报名挑战 → 打败王者全体剩余组别各 +2 分。
- 双人决战（`gameMode='solo'`）原本用「5 连胜强制休息」(`resting` 标记) 防止单一玩家霸台。
- 用户决定：**移除**双人决战的强制休息，改用**天下公敌**。
- 用户明确：先实测学生能否真的连胜，暂不加硬性连胜上限（第二层保险机制以后再加）。

## 需求

1. 把天下公敌机制移植到双人决战模式。
2. 彻底移除双人决战的强制休息。

## 机制设计

### ① 触发与晋升
- 守擂玩家连胜 **≥5 场** → 晋升王者 → 红底警告弹窗「👑 天下公敌！」+ 语音播报（复用 `showBigPopup`）。
- 连胜**持续累积**，不再被强制休息清零。
- 👑 王者标记：现有 `startBattleRound` 的 `kingCrown` 已自动支持两种模式，无需改动。

### ② 报名制挑战
- 天下公敌生效期间，**跳过轮盘抽签**，显示「谁愿挑战王者？」面板。
- 面板列出**所有存活且非王者**的学生，每人一个「🔥 报名挑战」按钮，由老师点选。
- 点选后：王者保留原角色，挑战者进入选角（复用 `startSingleCharSelect`）→ VS 倒计时 → 开战。
- 无人可挑战 → 「没有可挑战的对手了 → 王者夺冠！」→ 进排行榜（`showLeaderboard`）。

### ③ 讨伐奖励（用户选定：讨伐者 +2 且全体存活 +1）
讨伐成功那轮，**讨伐者共 +4**：

| 来源 | 加分 |
|------|------|
| 正常胜利 | +1 |
| King Slayer（打败 3+ 连胜对手） | +1 |
| 天下公敌奖励 | **+2** |
| **合计** | **+4** |

- **全体其他存活学生各 +1**（王者已被淘汰自然不含；讨伐者不再叠加，即 +1 给除讨伐者外的所有未淘汰学生）。
- 弹「⚔️ 讨伐成功！」+ 语音，天下公敌解除。

### ④ 解除与失效
- 王者被挑战者击败 → 按 ③ 发奖励并解除。
- 王者因「双方超时都输」被淘汰 → 天下公敌**自动解除**，恢复正常轮盘流程。
- 王者守擂成功 → 每轮结束都回到报名面板，直到有人成功推翻（王者连环）。

### ⑤ 强制休息移除
- 删除 `resolveRound` 中的强制休息块（现 3547-3609 行）。
- 同步清理 `resting` 相关死代码：轮盘候选过滤（`getWheelCandidateNames`、`spinForSlot`、`spinForBoth`）、`proceedAfterRound` 的 onStage 判断、`startBattleRound` 每轮开始的重置（3211-3212 行）。
- **双人决战从此无硬性连胜上限**——配合用户「先实测」的意图。

## 实现要点

### 状态
- 复用现有 `publicEnemyState`；双人模式中 `kingGroupIdx` 保持 `null`。

### trigger / dethrone 逻辑模式感知
- 从组别块（现 3637-3663 行）抽出，改为通用触发 + 按模式分支发奖：
  - `group`：现有逻辑不动——全体剩余存活非王者组各 +2（含讨伐组，讨伐组由此共 +4）。
  - `solo`：讨伐者 `wins += 2`；全体其他存活学生各 `wins += 1`。

### UI
- 复用现有 `#public-enemy-signup-panel`。
- 新增 `#public-enemy-student-buttons` 容器（与 `#public-enemy-group-buttons` 并列，按模式显示）。
- 奖励文案动态化（组别「全体剩余组别各 +2」/ 双人「讨伐者 +2，全体存活各 +1」）。

### 新增函数
- `showPublicEnemyDuelSignup()` — 显示面板、列出存活非王者学生。
- `choosePublicEnemyDuelChallenger(name)` — 点选挑战者，设 `battleState` 对应边，重置该侧技能槽，调用 `startSingleCharSelect(challengerSide)`。

### 流程接线
- `proceedAfterRound` 双人分支开头（questionIndex++ 与结束检查之后）：王者淘汰检查 → 若 `publicEnemyState.active` 则显示报名面板并 return。
- 双人决战开始处重置 `publicEnemyState` 并隐藏面板（对齐 `startGroupBattle` 的做法）。

## 边界情况
- 无人可挑战（只剩王者存活）→ 王者夺冠，进排行榜。
- 王者超时双输被淘汰 → 自动解除，恢复轮盘。
- 王者守擂成功 → 重复报名流程。
- 讨伐者推翻王者后自己累计到 5 连胜 → 触发新的天下公敌（王者连环）。

## 明确不做（YAGNI）
- 第二层保险（王者登基 / 连续未推翻强制退位）——用户以后再加。
- 组别模式现有天下公敌逻辑——保持不动。
- 双人决战强制休息以外的 `resting` 基础设施若清理有风险，保留无害死代码亦可。
